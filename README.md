# 吉林大学图书馆预约助手

一个基于 Python 的命令行工具，用于自动化吉林大学图书馆座位 / 会议室的查询、预约、取消，并提供后台签到守护、Token 有效性监控等辅助功能。

lib-assistant/中包含前后端代码（详见代码注释），可以搭配/dockerfile进行容器化部署，具备较完整交互功能，因其为异步预约架构，功能强大，但有被制裁的风险。
CLI_main.py 为可独立运行的CLI版本，稳定的同步预约，具备基本功能，服务器可搭配Screen等使用。


> ⚠️ **免责声明**：本工具通过调用图书馆预约系统的 Web API 实现自动化操作，仅供个人学习与提升预约效率使用。请遵守学校相关规定，合理使用，不要用于恶意占座或干扰系统正常运行。因使用本工具产生的任何后果由使用者自行承担。

## 功能特性

### 1. 座位预约
手动输入座位 ID、开始时间、结束时间进行预约。开始时间留空默认使用当前时间，结束时间留空默认 `21:00`。预约日期根据当前时间自动判断（详见下方"日期自动推断规则"）。

### 2. 会议室预约
手动输入会议室 ID、时间段、会议主题、参会人进行预约，时间输入规则与座位预约一致。

### 3. 取消预约
列出当前所有生效中的预约（座位 / 会议室），选择要取消的一项进行取消。

### 4. 分时段会议室预约
将某一段较长的时间自动拆分为多个符合规则的时间段，依次尝试为每个时间段提交会议室预约，并汇总每段的成功/失败结果。

### 5. 定时分段预约（后台任务）
在每天设定的触发时间（`SCHEDULER_TRIGGER_TIME`，默认 `21:00`）自动执行"分时段会议室预约"逻辑，无需人工值守。为提升成功率：
- 每段请求之间间隔 **0.5 秒**发送，避免瞬时并发压垮服务器；
- 若某段请求在发出后**未收到服务器返回**（超时/无响应），等待 **1 秒**后自动补发一次（最多重试一次）；
- 执行完成后可通过邮件汇报本次各时间段的预约结果。

### 6. 定时座位预约（后台任务）
在设定的触发时间（`SEAT_SCHEDULER_TRIGGER_TIME`）自动为指定座位（`SEAT_ID`）提交指定时间段（`START_TIME` ~ `END_TIME`）的预约请求，适合抢占开放瞬间的热门座位。

### 后台签到守护
自动监控当前生效的预约，判断是否需要签到/到馆确认；若检测到预约异常消失或被取消，会记录状态变化。

### Token 有效性监控
后台每隔固定时间（默认 10 分钟）检测 Token 是否仍然有效：
- 若确认 Token 已失效，通过邮件通知指定邮箱，提醒及时更新 Token；
- 网络层面的异常（连接超时、读取超时、连接被重置等）**不会**被误判为 Token 失效，也不会触发邮件通知，仅在控制台提示并跳过本轮检测。

### 彩色终端输出
统一的 `[✓] [✗] [!] [i] […] [→]` 状态图标 + ANSI 颜色，清晰区分成功、失败、警告、信息、进行中等不同状态。

## 配置说明

所有配置集中在脚本顶部的"配置区"，使用前请根据自己的账号信息修改：

```python
# ==================== 配置区 ====================
TOKEN = "junyue-server ..."          # 登录后从浏览器请求头中获取的 Authorization
BASE_URL = "https://libseat.jlu.edu.cn"

# 座位预约配置
SEAT_ID = 3421
START_TIME = "18:00"
END_TIME = "22:00"

# 会议室预约配置
MEETING_ROOM_ID = 38
MEETING_START_TIME = "17:00"
MEETING_END_TIME = "21:30"
MEETING_TITLE = "小组讨论"
MEETING_CONTENT = "无"
MEETING_ATTENDEES = [24545, 25420]   # 参会人用户 ID 列表

# 定时抢座配置（提前到达该时间后开始等待触发）
WAIT_UNTIL = None                    # 例如 "2026-06-18 08:00:00"，None 表示立即执行

# 定时分段预约触发时间（每天到此时间自动执行功能 5）
SCHEDULER_TRIGGER_TIME = "21:00"

# 定时座位预约触发时间（功能 6）
SEAT_SCHEDULER_TRIGGER_TIME = "07:00"

# 邮件提醒配置（Token 失效 / 定时任务汇报时发送）
EMAIL_SENDER = "your_email@qq.com"
EMAIL_RECEIVER = "your_email@qq.com"
EMAIL_SMTP_AUTHCODE = "your_smtp_authcode"
# ==================== 配置区结束 ====================
```

> 🔑 **如何获取 TOKEN**：登录 `bseat.jlu.edu.cn` 后按 F12 打开开发者工具 → Network 面板 → 勾选 Preserve log → 筛选 Fetch/XHR → 执行一次查询或预约操作 → 点击产生的接口请求 → 在 Request Headers 中找到 `Authorization: junyue-server ...` 并复制完整字符串。

> ⚠️ Token、邮箱地址、SMTP 授权码均属于敏感信息，**不要**上传到公开的代码仓库（如 GitHub 公共仓库），建议使用环境变量或 `.gitignore` 忽略本地配置文件。

## 日期自动推断规则

功能 1、2、5 会根据当前时间自动判断预约日期：

- 当前小时数 `≥ DATE_CUTOFF_HOUR`（默认 `21` 点）→ 预约**明天**；
- 否则 → 预约**当天**。

可根据图书馆放号规律修改 `DATE_CUTOFF_HOUR` 的值。

## 使用方法

```bash
python test_more.py
```

启动后会自动：
1. 检测当前 Token 是否有效；
2. 在后台启动 Token 监控线程（默认每 10 分钟检测一次）；
3. 在后台启动签到守护线程；

随后进入交互菜单：

```
请选择功能：
  1. 座位预约
  2. 会议室预约
  3. 取消预约
  4. 分时段会议室预约
  5. 定时分段预约 [开启/关闭]
  6. 定时座位预约 [开启/关闭]
  g. 查看守护状态
  q. 退出
```

- 输入数字或字母选择对应功能；
- 功能 5、6 为开关型任务，再次输入对应编号可关闭已启动的定时任务；
- 输入 `g` 可随时查看当前签到守护 / 定时任务的运行状态；
- 输入 `q` 退出程序（后台线程会随主进程一起结束）。

## 常见异常说明

| 异常信息 | 含义 | 是否视为 Token 失效 |
|---|---|---|
| `ConnectTimeoutError` / 连接超时 | 服务器负载过高或网络不稳定，未能建立连接 | 否 |
| `Read timed out` | 请求已发出但服务器未在超时时间内返回 | 否 |
| `ConnectionResetError` / Connection aborted | 连接被服务器或中间网络设备重置 | 否 |
| 接口返回 `401` / 提示未登录、Token 过期等 | Token 确实已失效 | 是，会触发邮件通知 |

以上网络层异常仅会在控制台打印提示并跳过本轮检测，不会误触发邮件通知，避免频繁误报。

## 注意事项

1. Token 有一定有效期，失效后需要重新从浏览器获取并更新配置区中的 `TOKEN`；
2. 定时任务（功能 5、6）依赖本机系统时间，请确保运行环境时间准确；
3. 长时间运行建议配合 `nohup` / `systemd` / `screen` 等工具后台运行，避免终端关闭导致进程退出；
4. 请勿将本工具用于恶意抢占资源、干扰他人正常使用图书馆资源的行为。
